# LandChain — Testing Documentation

## 1. Testing Overview

LandChain uses Hardhat and Chai for automated smart-contract testing.

Test file:

```text
test/LandRegistry.test.ts
```

The final test suite contains seven test cases.

---

## 2. Run Tests

From the project root:

```bash
npx hardhat test
```

Expected result:

```text
7 passing
```

---

## 3. Test Environment

The tests use:

- Hardhat 3
- Ethers.js
- Chai
- Solidity
- Local test accounts

The test helper deploys a fresh LandRegistry contract for each test.

---

## 4. Test 1 — Admin Assignment

### Purpose

Confirm that the deployer becomes the contract administrator.

### Expected behavior

```text
Contract admin == deployer address
```

### Result

```text
PASS
```

PASS

## 6. Test 3 — Duplicate Property Rejection

### Purpose

Prevent two properties from using the same property ID.

### Expected behavior

A second registration with the same ID reverts with:

```text
Property already exists
```

### Result

```text
PASS
```

## 9. Test 6 — Ownership Transfer

### Purpose

Confirm that the current owner can transfer a verified property.

### Expected result

```text
Current Owner  = Buyer
Previous Owner = Original Owner
```

The property status is updated according to the contract's ownership-transfer logic.

### Result

```text
PASS
```

---

## 10. Test 7 — Previous Owner Rejection

### Purpose

Confirm that an owner loses transfer authority after transferring ownership.

### Workflow

```text
Owner A
   ↓
Transfer to Owner B
   ↓
Owner A tries another transfer
   ↓
Transaction rejected
```

Expected error:

```text
Only property owner allowed
```

### Result

```text
PASS
```

## 12. Manual Frontend Testing

In addition to automated contract tests, the frontend should be manually tested.

### Wallet

- Connect MetaMask
- Disconnect/switch account
- Confirm wallet address display
- Confirm network status

### Authority

- Register property
- Verify property
- Search property
- View property details

### Owner

- View owned property
- Transfer ownership
- Confirm transaction
- Confirm updated owner

### User

- Search property
- Read property details
- Confirm restricted controls are unavailable

## 14. Testing Philosophy

The test suite focuses on the most important business rules:

```text
Correct authority
       +
Valid registration
       +
No duplicates
       +
Authorized verification
       +
Authorized transfer
       +
Ownership history
       =
Validated core contract behavior
```

---

## 15. Limitations of Testing

The current tests do not constitute a professional security audit.

Additional testing would be required for:

- Gas optimization
- Fuzz testing
- Formal verification
- Production network behavior
- Adversarial security testing
- Frontend penetration/security testing
- Legal/identity requirements
